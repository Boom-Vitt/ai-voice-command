## The blocker that had hidden all of this: the harness never ran

`/tmp/mictest_trace.txt` was **0 bytes** at the start of this session. That was not a stale
file — it was accurate. The harness had never produced a run.

`maybeArmAutostart`'s doc comment (main.swift, "Headless regression hook") instructs:

```
MICTEST_AUTOSTART=1 ~/Desktop/MicTest.app/Contents/MacOS/MicTest
```

and asserts *"Bundle identity and signature still resolve (Bundle.main is the .app), so TCC
is unaffected."* **That assertion is false.** Every such run dies with `SIGABRT` the moment
`LiveRecognizer.requestAuthorization()` is called. From the crash report:

```
"namespace": "TCC",
"This app has crashed because it attempted to access privacy-sensitive data without a usage
 description. The app's Info.plist must contain an NSSpeechRecognitionUsageDescription key"
```

The key **is** present and correct in the built `Info.plist` — verified with PlistBuddy.
`Bundle.main` does resolve to the `.app` (the trace prints the right bundle id and path).
TCC's usage-description lookup nevertheless does not honour it when the inner Mach-O is
exec'd directly. Four crash reports, one per attempted run, are in
`~/Library/Logs/DiagnosticReports/MicTest-2026-08-30-*.ips`.

The exit code is **0**, and the trace simply stops after the last startup line — which is
why this failed silently rather than announcing itself.

### The fix — no code change needed

`open(1)` forwards environment variables with `--env`, and `-W` blocks until the app exits:

```bash
open -W -n -g --env MICTEST_AUTOSTART=1 --env MICTEST_AUTOSTART_HOLD=50 -a ~/Desktop/MicTest.app
```

`-n` forces a new instance, `-g` keeps it from stealing focus. Launched this way TCC is
satisfied (`LiveRecognizer.requestAuthorization() -> true`) and the run completes.

**The doc comment at `maybeArmAutostart` should be corrected** — it currently sends the
reader straight into a guaranteed crash whose cause is invisible. Not changed here because
it is a comment about a decision, not a test-enabling change.

## Changes made (only these two)

**1. `MICTEST_AUTOSTART_HOLD` — main.swift, `maybeArmAutostart`.** The plan listed this as
"Optional". It is not optional any more: the default hold is 8.5 s and
`sessionRotationSeconds = 20` (LiveRecognizer.swift:151), so *the default headless run tears
down before a single rotation happens* and exercises none of Phase 2. Release is derived as
press + hold, quit as release + 6 s (the cloud pass's settle window). Value is clamped to
[1, 600] s, and a hold below 20 s now prints a line saying the run will not reach a seam —
so an absent `rotation:` line is never mistaken for a broken one.

**2. `HOTKEY: tap` trace line — main.swift, `hotkey.onPressStart`.** The hotkey is in
**toggle** mode (`wantsDictation.toggle()`), and it stays armed during headless runs. A
stray Right-Option tap therefore silently flips dictation off mid-run. Before this line the
only evidence was `endCapture(reason: "hotkey released")` — the identical sentence
`syncDictation()` prints for *every* route to `wantsDictation == false`, including failures.
This cost one full test round: a 45 s hold was cut to 36 s, the 40 s rotation never fired,
and the seam machinery looked broken when it was not. The line earned itself immediately —
it caught the next stray tap on the very next run (`22:45:17 HOTKEY: tap — wantsDictation ->
false (toggle mode)`).

## Why the remaining gap can't be closed without a human

> **Overtaken.** The reasoning below is sound about the *speaker* path and was verified twice.
> What it missed is that echo cancellation only sits between speaker and microphone: rendering
> `say` to a file and injecting it after the tap avoids it entirely. See
> `TEST-2026-08-30-seam.md`. A human is still needed to prove a *human voice* survives a seam.

Two attempts were made to feed the recognizer continuous speech automatically, so that a
seam would have something to lose and `+N` could be nonzero. Both failed, and the reason is
worth recording so nobody repeats it:

`say -v Kanya -f <thai text>` (47 s per pass, looped to cover the whole 50 s capture) was
played through the speakers while the harness ran. At the system volume of 69 **and again at
100**, the microphone's measured level was indistinguishable from an empty room —
`rms≈0.011`, against a noise floor of `0.010` — and the run produced `partials=0`, with both
seams reporting `code=1110 No speech detected`.

macOS applies voice-processing / echo cancellation to the input path, which subtracts the
machine's own output. **A Mac cannot dictate to itself through its speakers.** Feeding real
audio would need a second device, a loopback audio driver, or a person. (System volume was
restored to its original value of 69 afterwards.)

## Stale plan items found while testing

- **`MICTEST_FLUSH_SEAM=1` no longer exists as an env gate.** Phase 0 specified it as the
  probe that would emit `+<chars> beyond last partial`. It was absorbed into the mechanism
  when Phase 2 landed — every rotation is now a flush, so the measurement is a routine trace
  line. `grep 'environment["MICTEST_FLUSH_SEAM"]'` returns nothing; only a historical comment
  in `LiveRecognizer.swift` survives, and it says so explicitly.
- Consequently **the string `seam-flush` will never appear in a trace.** Plan verification
  item 2 greps for `partial-lag\|seam-flush`; the first half is live, the second is dead.
  The line to grep for now is `rotation: flushed final … +N chars beyond partial at flush`.
  **The wording changed** when review finding 3 was fixed: it read `… beyond last partial`
  through 2026-08-30, so a grep written against the old string silently matches nothing on a
  current build, and traces captured on or before that date will not match the new one. Greping
  `rotation: flushed final` alone spans both.

## Reproducing

```bash
cd MicTest && ./build.sh
pkill -9 -f "MicTest.app/Contents/MacOS/MicTest"; : > /tmp/mictest_trace.txt
open -W -n -g --env MICTEST_AUTOSTART=1 --env MICTEST_AUTOSTART_HOLD=50 -a ~/Desktop/MicTest.app
grep -nE "rotation:|replay:|FINAL:|HOTKEY:|AUTOSTART SUMMARY" /tmp/mictest_trace.txt
```

Two cautions, both learned the hard way this session:

- **Kill stray instances first.** The trace is opened `O_APPEND` and never truncated, so two
  live instances interleave into one file with *different* counters — which reads exactly
  like one app doing everything twice. One round was lost to this before it was spotted (the
  tell: capture lines continuing *after* `=== MicTest terminating ===`).
- **The app types into whatever has keyboard focus.** These runs injected real text
  (`injectedChars=127` on one round) into the frontmost window from ambient room noise.
