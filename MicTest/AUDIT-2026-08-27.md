# MicTest audit — 2026-08-27

Findings from a parallel Opus audit of every source file. Baseline commit `9bba5c9`.

Ranked by **user impact**, not by subsystem. Each entry states how it was
established: CONFIRMED means reproduced or proved from code plus field data;
PLAUSIBLE means the mechanism is proved but the trigger is not.

Field data throughout is `/tmp/mictest_trace.txt` (4029 lines, 19 launches) and
OSLog. Note that everything logged before the `O_APPEND` fix in this same tree
was written by a racing `seekToEnd`+`write` pair measured to lose **53 %** of
lines under contention — absence of a line is therefore never proof of absence
of the event.

---

## P0 — affects the user during ordinary work

### 1. Right-Option in a chord turns the microphone on and types into the document
CONFIRMED · `HotkeyMonitor.swift:254`, `:349-366` · **not yet fixed**

The app is in toggle mode (`main.swift:1270-1278` wires `onPressStart` to
`wantsDictation.toggle()` and `onPressEnd` to an explicit no-op). The event tap
masks **only** `.flagsChanged`, so the monitor never sees a `keyDown` and cannot
tell "Right-Option tapped alone" from "Right-Option held as a chord modifier".
Every down-edge of keyCode 61 toggles.

On a MacBook, Right-Option sits beside the arrow cluster. Option+Left/Right for
word navigation therefore starts capture, and partial transcripts begin being
injected into the document being edited. An odd number of such chords leaves the
microphone live indefinitely.

Left-Option is unaffected — the device-bit read (`0x40`) genuinely distinguishes
the two, and that part of the file is its strongest design.

`.listenOnly` is the right choice (suppressing Right-Option would break it for
every other app), so the gesture must be *cancelled* on seeing a chord rather
than consumed. That needs `.keyDown` in the mask, whose own cost is a listen-only
tap over every keystroke typed outside Secure Event Input. That trade is a
product decision, not a mechanical fix.

### 2. Microphone can stay live with no reachable off-switch
CONFIRMED · `HotkeyMonitor.swift:409`, `:466`, `main.swift:1278` · **not yet fixed**

All four stuck-on defences (`synthesizeReleaseIfHolding`, `maxHoldDuration`,
the state poll, `onPressEnd`) are gated on `isHolding`, which in toggle mode is
true only for the ~100 ms a physical tap is down. They are inert.

Lock the screen or click a password field → Secure Event Input kills every
session event tap. `pollHealth` correctly notices and calls
`synthesizeReleaseIfHolding`, which returns immediately at its `guard isHolding`.
`wantsDictation` stays true, `endCapture` is never called, and capture continues.
The only off-switch is the hotkey, dead for the same reason.

There are no `willSleep` / `didWake` / `screenIsLocked` observers anywhere in the
project, and nothing acts on `isHealthy` beyond menu text.

### 3. Thai text is corrupted on revision — the original reported symptom
CONFIRMED, reproduced · `main.swift:2140-2142` · **not yet fixed**

```swift
let typedCount = injectedForUtterance.count
guard text.count > typedCount else { return }
let suffix = String(text.dropFirst(typedCount))
```

`dropFirst` never verifies that `injectedForUtterance` is a prefix of `text`.
Reproduced in a standalone harness — 5 of 6 sequences wrong:

| partials | on screen | expected |
|---|---|---|
| `เดียว dep` → `เดี๋ยว deploy ให้` | `เดียว deploy ให้` | `เดี๋ยว deploy ให้` |
| `ก` → `ก่` → `ก่อ` → `ก่อน` | `กอน` | `ก่อน` |
| `เดีย` → `เดียว` → `เดี๋ยว` → `เดี๋ยวนะ` | `เดียวนะ` | `เดี๋ยวนะ` |
| `ไม่ เป` → `ไม่เป็นไร` | `ไม่ เปไร` | `ไม่เป็นไร` |
| `👩` → `👩‍` → `👩‍💻` → `👩‍💻 hi` | `👩 hi` | `👩‍💻 hi` |

Two distinct mechanisms, and a fix addressing only one will look right and stay
broken:

- **Count-stall.** Adding a tone mark to an existing cluster does not raise
  `text.count` (`เดียว` and `เดี๋ยว` are both 4 clusters), so the gate returns and
  the mark is lost *permanently* — the next growing partial slices past it. The
  gate condition itself is wrong: it must be "text differs from what I typed",
  not "text is longer".
- **Misalignment.** A word-merge revision passes the gate and `dropFirst` takes
  the wrong slice.

Correct handling of both is delete-and-retype, which routes into
`replaceLastInserted` — dead code today (finding 4) but **verified correct**
(grapheme→UTF-16 conversion checked: 5 clusters → 7 units). Part of the fix is
wiring up existing correct code, not writing new code.

### 4. The divergence detector cannot fire; three counters are fiction
CONFIRMED · `main.swift:2194` (`repairDivergence`, zero call sites)

`repairDivergence` is never called. It is the only writer of `divergences` and
the only caller of `TextInjector.replaceLastInserted`. Therefore:

- `divergences=0` in every trace line is **not a health signal** — the counter
  cannot be non-zero. Same for `injectFailures` and `SECURE INPUT`: zero across
  all 4029 lines because the paths do not run.
- The "stop typing rather than guess" safety story in the file headers does not
  execute.

Any past verification that cited these counters as evidence was measuring
nothing.

### 5. Retracted text is never removed
CONFIRMED · `main.swift:2141`

When a partial gets shorter, `deliver` returns early and leaves the retracted
characters in the document. Field proof, from lines where the final's own attempt
is already included:

```
14:19:53  FINAL: 6 chars, injected 22 chars, diverged=false
14:59:22  FINAL: 7 chars, injected 27 chars, diverged=false
15:02:03  FINAL: 2 chars, injected 8 chars, diverged=false
```

16 characters of retracted Thai left behind, flagged as not diverged.

The same fact is why the reconciliation cannot currently eat text the user typed
by hand: it cannot delete anything at all. **Enabling deletion introduces that
risk for the first time** — it was chosen deliberately, and the guards in
`replaceLastInserted` are what must hold.

## P1 — privacy

### 6. Dictated text sits on the general pasteboard
CONFIRMED · `TextInjector.swift:735-765`

OSLog shows the Accessibility write path refused **158 of 158 times** in the
field (`TextInjector.swift:341`), so every real injection fell through to the
clipboard path. The transcript is placed on `NSPasteboard.general` for up to
700 ms, once per partial. Any clipboard manager (Raycast, Maccy, Alfred, Paste)
has a history of the user's dictation.

The file's own privacy note forbids logging transcripts even truncated.

### 7. Consent text promises on-device; 12.3 MB of speech was uploaded
CONFIRMED · `Info.plist` usage strings

`NSSpeechRecognitionUsageDescription` says *"uses **on-device** speech
recognition"*. Neither usage string mentions fal.ai or any network transmission.

Field totals: **42 completed round trips, 12,875,148 WAV bytes** (~16.4 MB on the
wire after base64) to a US datacenter. p50 3.3 s, p90 6.1 s. **26 % (11/42)
returned an empty transcript** — worth investigating on its own.

The feature is genuinely opt-in and was switched on deliberately; this is stale
disclosure, not covert exfiltration. The toggle was verified to prevent **all**
egress when off — no auth probe, no warm-up, no retry queue. TLS is correct with
no bypass path, the API key is outside the repo at mode 600 and is **not** in
git, and no transcript text reaches the trace.

### 8. Cloud toggle OFF does not stop an in-flight result rewriting the document
CONFIRMED · `main.swift:2682-2695`, `:2496`

`toggleCloud` never cancels `cloudTask`, and `applyCloudResult` never re-reads
`cloudEnabled`. A result landing 3–9 s after the user switches the feature off
still rewrites their text. (`autoCorrectEnabled` *is* read live at apply time —
the master toggle is the inconsistent one.)

## P2 — the watchdog and its evidence

### 9. RMS is sampled, not averaged — keyboard clicks arm the ladder
CONFIRMED · `main.swift:1697-1701`

Measured: the tap buffer is **4800 frames at 48 kHz = a 100 ms window**, written
last-write-wins, read by a **1 Hz** timer that therefore discards 9 buffers in
10.

Estimator spread for stationary noise is **σ = 0.088 dB** — the "short window
makes σ large" concern is off by ~50×. The real mechanism is impulsive
non-stationarity:

| scenario | σ (dB) | p99/p50 | 1 Hz samples over threshold |
|---|---|---|---|
| stationary room tone | 0.09 | 1.02× | 0 / 1200 |
| + HVAC drift ±4 dB | 2.83 | 1.60× | 0 / 1200 |
| **+ keyboard clicks (12/min)** | **3.39** | **17×** | **26 / 1200** |

σ is the wrong statistic — the 2.83 dB case never fires and the 3.39 dB case
does. A 30 ms click dominates a 100 ms window while the fast-fall floor stays
pinned. **Fix direction: average across the full 1 s tick instead of sampling
the last buffer** (dilutes a click ~10×). A shorter window would make this worse.

Room scenarios are synthetic; the window, buffer size, cadence and analytic σ are
measured. Threshold crossings are not predicted `pkill`s — the ladder's other
gates were not modelled.

### 10. Watchdog silences itself permanently when tier 3 is OFF (the shipped default)
CONFIRMED · OFF path, `bounceBackoff` · **fix in flight**

`suppressedBouncesSinceRestart` ratchets monotonically on the OFF path; at 3 it
pins `bounceBackoff` at 48 s. But the overlap rotation stamps
`lastRecognizerEventAt` every ~18–26 s even during a total wedge, so the maximum
achievable event-free gap is ~26 s and `> 48` is unsatisfiable forever.

Measured 30 runs × 4 environments: **1.7–2.0 `WOULD FIRE` lines, then silence for
~1050 s.** Tiers 1 and 2 die with it.

### 11. The evidence that armed a strike is never recorded
CONFIRMED · `loudTicksSinceRecognizerEvent` zeroed before all nine watchdog trace
lines print · **fix in flight**

The lines print the room *now*; the strike was caused by up to 26 s of history
that is discarded unprinted. The printed `rms` is frequently *below* `thr` on the
firing tick — correct by design, unreadable in practice.

### 12. Trace lines were being lost
CONFIRMED, fixed in this tree · both `trace()` writers

Two writers, two handles, `seekToEndOfFile()` + `write()` with no `O_APPEND` and
no lock. Measured with 8 threads × 3000 lines: **12,700 of 24,000 lines lost
(53 %)**, as whole-line overwrites — invisible in the file. Survivors were
well-formed, so the loss cannot be spotted by inspection. Now `O_APPEND` in both:
0 lost.

## P3 — latent, correct-but-inert, and traps

- **NaN traps `Int16(_:)`** — `AudioPipeline.swift:584-585`. Swift's `min`/`max`
  return the NaN operand, so the clamp is a no-op and `Int16(nan * 32767)` is a
  hard crash (reproduced, SIGTRAP). Reachable only with the cloud pass on plus a
  NaN from a virtual/aggregate device. One-line fix.
- **`flush()`'s duration gate can never pass** — `AudioPipeline.swift:443` needs
  `count >= 6400` but `:302` pins `count` to 4000 whenever `speech == 0`. The
  comment states the gate was changed to duration *because* of a measured
  production failure; that fix is inert. Trace shows 4 occurrences.
- **`emitFinal`'s retained tail is silently discarded** in a bounded window
  (consumer 11–29 s behind, low speech duty) — up to 14.85 s of audio, against a
  contract that promises the tail becomes the next chunk's head.
- **Converter errors captured and never read** — `AudioPipeline.swift:325`,
  `:331`. A permanently failing converter silently kills the cloud pass while the
  frame watchdog (which counts raw tap frames independently) reports health.
- **`AudioPipeline.level` is dead code** — zero readers project-wide. Whoever
  wires it into the noise-floor tracker must know it is post-anti-alias at 16 kHz
  and reads **−4.78 dB** low for flat noise (−0.33 dB pink, −0.00 dB speech)
  versus the full-band value the constants were tuned against.
- **Realtime conversion runs when nobody consumes it** — `main.swift:1690`. With
  the cloud pass off (the default) the chunk loop never starts, yet every 100 ms
  buffer is still converted 48 k→16 k on the render thread under a lock.
- **`UInt16(UserDefaults.standard.integer(forKey:))` traps** —
  `HotkeyMonitor.swift:202`. `defaults write … hotkeyKeyCode -1` kills the app at
  launch before `applicationDidFinishLaunching`, with no diagnosable message.
- **An in-range non-modifier `hotkeyKeyCode` is silently dead** —
  `HotkeyMonitor.swift:333-345`. Nothing validates that the configured key is a
  modifier the `.flagsChanged` mask can observe; `isHealthy` still reports true.
- **`FalClient` destroys cancellation identity** — `FalClient.swift:329-335`
  flattens `URLError.cancelled` into `ClientError.transport`, so
  `main.swift:2478` can never see a cancellation. Latent today; **arming it is a
  precondition of fixing finding 8**, and would then report every deliberate
  cancel to the user as a failure. `WhisperClient.swift:173-176` gets this right.
- **Superseded cloud results are counted nowhere** — `main.swift:2496-2500`.
  6 paid, completed round trips in the field went into no counter.
- **An empty transcript is counted as an error** — `main.swift:2502-2507`
  conflates "network failed" with "model heard nothing" (26 % of traffic).
- **`WhisperClient` is unreachable and its flag is decorative** —
  `localWhisperFallbackEnabled` is a top-level `let false` read in exactly one
  `trace()` interpolation. There is no branch to revive. Revival hazard: it has
  no VAD of its own and its doc warns it "invents plausible speech" on silence.
- **The "HID claims key up while holding" compensation is inert** and its cited
  evidence is absent from the trace (possibly a victim of finding 12). The
  remapper hypothesis is disproved (`hidutil property --get UserKeyMapping` →
  null). `keyStateMissThreshold` is declared and never read. One configuration
  was never tried: `CGEventSource.flagsState(.hidSystemState)` masked with `0x40`.
  All moot until finding 2 is addressed.

## Verified clean

Checked and found sound: no API key in git; the cloud OFF toggle genuinely
prevents all network egress; TLS validation intact with no delegate bypass; no
transcript text in the trace; audio buffering bounded by a preallocated 30 s
ring; `TextInjector` concurrency clean under `-swift-version 6`; the clipboard
restore bookkeeping; `HotkeyMonitor`'s tap lifecycle, device-bit design, and
`.tapDisabledBy*` handling; `AudioPipeline`'s lock discipline, buffer lifetime,
chunk arithmetic, and teardown; `TextInjecting.swift` (protocol only); and
`replaceRecentText`'s guard stack, which is markedly more defensive than expected
(ambiguity guard, drift absorption, collapsed-caret requirement, bounded search
window).
