The Thai Dictation Gap

Four premises went into this research. Three of them were false. The one that survived is narrower, sharper, and — measured on real hardware today — fixable with an eight-word glossary.

MEASURED — run on this machine DOC — vendor documentation 3P — third-party evaluation UNVERIFIED

01Bottom line

Build it — but not the product you set out to build, and not for the reason you expected.

“Nobody serves Thai dictation”

False

“US incumbents ignore code-switching”

False

“Speaking Thai beats typing it”

Unsupported

“Thai + English in one sentence is broken”

True & fixable

Wispr Flow specifically optimised Thai. Windows 11, Google and every Whisper wrapper list it. Wispr even sells Hinglish as a named language in India at a 72% discount, with UPI payments — so the “incumbents ignore mixed languages” thesis is not merely unsupported, the opposite is documented.

The product is not “faster dictation.” It is “we write your English words in English.”

For a dictation tool, silently fabricated sentences are the worst possible failure — the user pastes confident nonsense into a client email. And auto is not a third option: byte-identical to language=th.

Three failure modes, only one repairable

  • Systematic transliteration — เรฟาเทอร์ for refactor. Phonetic shadow survives; likely recoverable.
  • Substitution into a real word — meeting → มีทิ้ง, which is readable Thai. refactor → “Refrigerator”, an ordinary English word. Nothing downstream can flag this.
  • Merge and loss — branch main (two tokens) → รันสมีน (one). Boundary gone.

A repair dictionary is impossible. Two runs of the identical file produced ดีโพล้อย and ดิบโล้ย. There is no stable key — repair must be a semantic pass, never a lookup.

The finding the business rests on REVISED

Re-running at full model scale overturned two of the earlier conclusions. The headline — the Latin-script barrier is soft — survives and is now confirmed twice over. The mechanism changed.

Correction 1 — transliteration is scale-dependent, not universal. Everything above was measured on ggml-small (487 MB). On large-v3, at language=th, with no prompt and no configuration at all:

The <|th|> token is not a hard Latin-script ban — a large enough model crosses it unaided. This strengthens the local recommendation: Pathumma-Whisper-L3 and Typhoon-Whisper-L3 are both large-v3 fine-tunes, so they inherit this before any Thai tuning.

Correction 2 — the glossary is not monotonic. It can subtract. At large-v3, the same eight-word glossary regressed refactor function from correct Latin back into Thai script — with both words in the glossary — and deleted meeting entirely. It did recover all four of commit, push, branch, main. Replicated 3× per condition; both reproduce 3/3. Systematic, not noise.

Both model sizes land at 5/7 with the glossary — but not on the same five words. The glossary changes which terms survive, not reliably how many.

A deleted word is worse than a transliterated one. Transliteration leaves a phonetic shadow a repair pass can use. Deletion leaves nothing — no repair layer can recover a word that was never emitted, and the user cannot see what is missing. Track deletion rate as a first-class metric alongside ETR.

The primary lever is base-model scale. The glossary is a secondary, double-edged tool — evaluate it per term, never assume it helps.

Still an integration problem rather than a research frontier — but “just add a glossary” was too simple.

Caveats. Audio is synthetic (macOS say -v Kanya), so the pattern is the finding, not the absolute numbers. initial_prompt caps at 224 tokens, introduces spurious commas, and corrupted an adjacent Thai word (ขึ้น→คืน). One bonus result: large-v3 was byte-stable across all 12 runs while small produced two different spellings of the same file — larger models are more repeatable, not merely more accurate.

Why the glossary is a moat, not a feature

A glossary only helps if it holds the right words for this utterance. A desktop app knows what a cloud API cannot: the frontmost application, the current git branch names, identifiers in the open buffer, dependency names, and the user’s accepted corrections. That is a per-utterance, context-derived glossary — a moat mapped directly onto a measured mechanism.

03Why the gap persists

Not an oversight. Four independent causes.

  • Whisper is architecturally biased against it — though not absolutely. “Whisper’s language and task tokens cannot explicitly direct the model to do code-switching ASR, with each language token only representing one language.” That claim is about what the token can be directed to do, and it stands — but a large-v3 model crosses the barrier anyway, unprompted. So Whisper-based competitors inherit a handicap, not an impossibility, and the model size they ship decides how badly they suffer it. Superwhisper, MacWhisper, VoiceInk, Better Dictation, Spokenly and Handy all carry it — and several default to small models for speed.
  • The cloud tier excludes Thai specifically. Deepgram’s code-switch model: 10 languages, Thai absent. AssemblyAI’s: 18 languages, Thai absent — Vietnamese is in. Speechmatics ran a deliberate Southeast Asia bilingual push, shipped Mandarin/Malay/Tamil/Tagalog-English, and skipped Thailand.
  • Academia has never looked. CS-FLEURS — 113 language pairs, including a 45-pair low-resource set — contains no Thai. A 127-paper review of code-switching ASR: “Thai receives no mention.” SEAME, the South-East Asia code-switching corpus, skips Thailand. No Thai-English code-switch speech corpus exists.
  • The Thai NLP community scores the fix as a defect. Typhoon2-Audio’s “Code-Switching” benchmark defines accuracy as: “The response does not contain characters from other languages.” A model scoring 100% never emits deploy in Latin script.

The people who could fix this don’t speak Thai. The people who speak Thai are optimising a benchmark that punishes the fix.

But the clock is real. Wispr announced Canto alongside its $280M Series B — its first proprietary speech model, explicitly targeting “half the world [that] moves between languages… often inside a single sentence.” Their current docs still say the opposite. Window: roughly 18–24 months.

The two moats nearly cancelled each other

Every local Thai path is a single-language decoder. Apple’s SpeechTranscriber has no Thai at all; SFSpeechRecognizer is one locale per instance by construction; Whisper has one language token. So “your voice never leaves your laptop” and “we write your English words in English” looked mutually exclusive — until the glossary result rescued both.

That is the load-bearing result of this report — and the revision strengthens it: a large-v3-class local model emits Latin-script inserts unprompted, so it now rests on model choice rather than a prompting trick. If it fails to replicate on real recorded speech, the two moats separate again and you must choose one.

This corrects a published blog claim that SpeechTranscriber covers Thai across ~34–42 locales. English-only competitors get a free, fast, private, zero-cost OS engine. For Thai, nobody does — everyone must ship their own model, which raises your cost and every competitor’s.

Latency: two clocks, and one invisible bug

Don’t stack Nielsen, Doherty and RAIL into one budget — they measure different things. The literature requires acknowledgment within 100 ms, not text. Text gets ≤500 ms as a stretch, ≤700 ms to stay competitive. Push-to-talk is the largest free win: it replaces a speculative silence timeout with a deterministic finalize event, and AssemblyAI’s default 1536 ms turn-silence alone blows a 700 ms budget by 2×.

The trap. Push-to-talk only pays off if you both disable server-side turn detection and explicitly force-finalize on key release. Miss either and it silently degrades to voice-assistant latency. It doesn’t error — it just feels slow.

MEASURED Mic warm-up on Apple Silicon: 2,568 ms cold on first access, ~250 ms warm, 68 ms for a kept-warm CoreAudio unit. Pre-warming is mandatory, not an optimisation.

Text injection — and why Thai forces the clipboard

Electron apps (VS Code, Slack, Notion) don’t build an accessibility tree, and the flag that would build it is itself broken — so clipboard paste is the only reliable route. Elevated Windows and password fields accept nothing at all; detect and say so.

MEASURED With the Thai Kedmanee layout active, synthetic keystroke injection re-translates virtual keycodes — Apple’s own docs concede frameworks “may ignore the Unicode string… and do their own translation.” Add an undocumented ~20-UTF-16-unit delivery limit: the first 20 Thai graphemes are 26 UTF-16 units, so naive chunking splits tone marks from their base consonants and produces visible mojibake.

The second, quieter win

  • “Auto-punctuate” in Thai means auto-space. Thai has no sentence period; the Royal Society publishes 22 numbered spacing rules, and a space is required at every Thai↔Latin boundary. Thai dictation users report the words come out roughly right and the spacing comes out wrong — which a cheap cleanup pass fixes. This may beat code-switching on perceived quality.
  • Buddhist Era dates are the top silent-corruption risk. พ.ศ. 2569 → พ.ศ. 2026 looks well-formed and is wrong. Mask years before the model call.
  • Word segmentation is free on macOS. NLTokenizer handles Thai correctly with no Python. This matters commercially: naive whitespace counting under-bills Thai users by 7.1×.
  • The token tax is ~2.5× smaller than folklore. On o200k Thai costs only 1.33–1.85× English, not the 4× commonly claimed. Free lever: Thai numerals ๒๕๖๙ cost 7 tokens versus 2 for 2569 — normalise first.

06The competitor, and the law

Wispr Flow is the real competitor, not Glaido — $280M Series B at $2B, 60 billion words written, “almost all of the Fortune 500”. Their exposed flank is privacy, and it is unusually wide:

  • Context Awareness is on by default and transmits a screenshot of your screen with each dictation.
  • Audio and transcripts “may be used to evaluate, train, and improve Wispr’s models. This is the default for trial and standard accounts.”
  • No on-device option exists at all. Their DPA lists 34 sub-processors, every one US-located.
  • SOC 2 Type II is claimed in marketing while their own security FAQ says it is “not yet issued”.
  • In late 2025 they were caught sending screenshots of active windows to the cloud — and banned the user who reported it.

Thailand’s PDPA turns that flank into a legal argument. Thailand has published no adequacy whitelist, so sending Thai voice abroad requires either standard contractual clauses with every foreign sub-processor, or consent obtained after expressly warning the user the destination lacks adequate protection. Local-only processing deletes that obligation entirely — no transfer occurs.

A design decision with direct legal force: keep voiceprint and speaker-ID out of v1. Transcription without a speaker model is ordinary personal data. Add voice enrolment and you fall under §26 sensitive biometric data, requiring separate explicit consent.

On price: Wispr costs a Thai buyer ฿392–490/month — at or above Netflix Premium (฿419), Thailand’s most expensive mainstream subscription, for a typing accessory used by one person. But don’t treat that as structural: Wispr already charges ₹400 (~฿137) in India and accepts UPI. Price against the ฿200–320 an income-tiered Wispr Thailand would plausibly charge — which keeps ฿199–299/month plus a ฿2,900–3,900 lifetime tier viable. A one-time purchase is the one structure a subscription-native incumbent is least willing to match.

Only 22.6% of Thai adults hold a credit card, while PromptPay has near-universal coverage and Stripe Thailand supports it natively. But note the B2B trap: you cannot issue a compliant ใบกำกับภาษี without VAT registration, and many Thai companies won’t buy without one. B2C self-serve is dramatically lower-friction — don’t chase Thai enterprise logos early.

07The build sequence

STEP 0

Record 20 utterances in your own voice — ½ day

Everything measured so far used synthetic speech. You are the target user. Highest leverage-to-cost step available, and it validates or kills the entire glossary finding.

STEP 1

Three-way bake-off — 2 days · under $1

Same clips through Soniox, Gemini 3 Flash and Pro, and Pathumma-Whisper + initial_prompt. Score every engine both with and without the glossary — prompting was measured to subtract at large-v3. Track ETR (English-Term Retention), deletion rate, and Thai CER. Plain WER is invalid for code-mixed text.

STEP 2

Benchmark the incumbents on identical clips — ½ day · ~$15

Wispr Flow, Monologue, Superwhisper. This decides the pitch. Clean consistent Latin inserts means the technology wedge is dead and this is a distribution business. Flip-flopping means you have a ten-second demo video.

STEP 3

Measure repair recoverability blind — ½ day

Strip ground truth, hand outputs to an LLM cold, score recovered / substituted / lost. The substituted-plus-lost fraction is the hard ceiling on any repair strategy.

STEP 4

Unblock the free Apple path — 1 day

Wrap the probe in an .app bundle with NSSpeechRecognitionUsageDescription, then test SFSpeechRecognizer(th-TH) with and without contextualStrings. Zero cost, zero download if it works.

STEP 5

Build the glossary engine — 1 week

This is the moat. Per-utterance English glossary from frontmost app, git branch names, open-buffer identifiers, dependency names and accepted corrections. 224-token budget, English only, rotated by context. Because prompting can regress or delete terms, this needs a per-term A/B harness, not a static word list.

08Honest risks

  • Wispr’s Canto is aimed directly at this. An 18–24 month window, not an open field.
  • You’d be entering behind on Thai — Wispr already has Thai TikTok reviews and Thai Facebook coverage.
  • The dominant Thai code-mixing pattern is lexical insertion — English nouns in Thai syntax — which is the case Wispr’s docs claim it does handle. The surviving gap is output script, not capability. Step 2 confirms or kills this.
  • The market is thin. Thai average wage ฿15,316/month; Thailand shows 195 iOS ratings against India’s 2,572. Realistic scale is a ฿10–50M/year local software business, not a venture outcome.
  • The leader is commoditising the category — Wispr’s free tier now includes 100+ languages and a notetaker. Selling “better dictation” means competing with free.

09What I could not verify

  • Real-voice replication of the scale and glossary results. All audio was synthetic. This is Step 0.
  • Whether Pathumma / Typhoon Whisper inherit large-v3’s unprompted Latin-script behaviour. Inferred from shared lineage, not measured on those models.
  • Soniox’s Thai quality. Vendor marketing only; zero published Thai WER.
  • Gemini’s Thai accuracy at the Flash tier. The cheap pricing is Flash; the only Thai benchmark is Pro. These do not currently meet.
  • Whether an audio LLM actually obeys a script-constraining instruction for Thai. No vendor documents it — and it is the crux of the top recommendation.
  • Deepgram’s opt-out discount — whether declining data-training forfeits ~50%. Ask in writing.
  • Windows AI Speech Recognition’s language list. Microsoft publishes none. If Thai is absent, Windows mirrors macOS.
  • Reddit was unreachable from the research environment.
